# Network audit — "zero network call"

_Audit performed on 4 November 2026 on the code of this repository (Expo SDK 58)._

**Result: Moni performs no network call at runtime, on any platform.** The only network traffic is the loading of
the web version itself from its host (like any website) and, on the web, the service worker pre-caching those same
files from the same origin.

## 1. Application code

Search over `app/` and `src/` (excluding tests) for `fetch(`, `XMLHttpRequest`, `WebSocket`, `EventSource`,
`sendBeacon`, `axios`, `http://` / `https://` URLs, `Linking.openURL`, `openBrowserAsync`, `downloadFileAsync`,
`navigator.onLine`: **no occurrence**.

ESLint forbids `fetch`, `XMLHttpRequest`, `WebSocket` and `EventSource` (`no-restricted-globals`) and the imports of
`axios`, `expo-updates` and `expo-web-browser` (`no-restricted-imports`), so a regression fails the CI.

The only URLs of the project are the sources of the regulated rates (Légifrance, Service-Public.fr…), displayed as
selectable **text** on the "Taux des livrets" page; the app never opens or requests them.

Web-only file handling uses `Blob` + `<a download>` for exports and the `File` object returned by the file picker
for imports (no `fetch`, not even of a `blob:` URL).

## 2. Dependencies

Runtime dependencies (`package.json`): expo, expo-router, expo-sqlite, expo-file-system, expo-document-picker,
expo-sharing, expo-crypto, expo-local-authentication, expo-secure-store, expo-constants, expo-linking, expo-splash-screen, expo-status-bar, expo-system-ui,
@react-native-async-storage/async-storage, dexie, @noble/hashes, @noble/ciphers, react-native-svg,
react-native-screens, react-native-safe-area-context, react-native-gesture-handler, react-native-reanimated,
react-native-worklets, react-native-web, react, react-dom.

- **Not installed**: expo-updates (OTA), expo-dev-client, expo-notifications, expo-web-browser, expo-network,
  expo-insights, expo-application, any analytics / crash reporting SDK (Sentry, Firebase, Bugsnag…). Checked in
  `node_modules`.
- `app.config.ts`: `updates.enabled: false`.
- Network-capable code present in dependencies, **never called by Moni**:
  - React Native core (`fetch`, `XMLHttpRequest`, `WebSocket` APIs) — available but unused;
  - expo-file-system (download / upload APIs) and expo-asset (remote assets) — unused; release builds embed all
    assets;
  - react-native-svg `SvgUri` (loads an SVG from a URL) — unused, icons and charts are inline SVG;
  - expo-router server data loaders and web worker polyfill — unused features (no server, `web.output: single`).
- **Development only** (stripped or inactive in release builds, `__DEV__ === false`): Metro bundler and hot reload
  WebSocket, React Native DevTools / LogBox, expo-sqlite DevTools client, expo-keep-awake.

Production web bundle scan (`dist/_expo/static/js/web/*.js`): 0 `XMLHttpRequest`, 0 `new WebSocket`,
0 `EventSource`, 0 `sendBeacon`; 11 `fetch(` occurrences, all in the unused library code paths listed above.

## 3. Platform-level guarantees

| Platform | Guarantee                                                                                                                                                                                                                                                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Android  | Production builds declare **only `USE_BIOMETRIC` / `USE_FINGERPRINT`** (app lock, no network access): `INTERNET` and every other permission are removed with `tools:node="remove"` (`android.blockedPermissions`, checked in the manifest generated by `expo prebuild`). Without `INTERNET`, the OS refuses any socket opened by the app or a library. |
| iOS      | iOS has no network permission. Guarantee = code and dependency audit above; no tracking domain and no collected data are declared in the privacy manifest (`NSPrivacyTracking: false`).                                                                                                                                                                |
| Web      | The production `index.html` carries a Content-Security-Policy with **`connect-src 'none'`**: the browser blocks every `fetch`, XHR, WebSocket, EventSource and beacon issued by the page (verified: a `fetch` from the page fails). Fonts, images and scripts are restricted to the same origin (`'self'`): no CDN, no Google Fonts.                   |

Development builds keep `INTERNET` on Android because the JavaScript is loaded from Metro.

## 4. Service worker (web)

`dist/sw.js` (generated by `scripts/build-pwa.mjs`) pre-caches the files of the current version and serves them from
the cache. It only handles same-origin `GET` requests for the app's own files; it never contacts another host and
never sends user data. Once loaded, the web version works offline (verified with the server stopped).

## 5. Developer tooling (not part of the app)

Expo CLI, npm, EAS and `expo-doctor` use the network during development and builds. Expo CLI usage statistics are
disabled with `EXPO_NO_TELEMETRY=1` (EAS profiles and CI).
